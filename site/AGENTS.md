## This site

- **Landing (`/`) and pricing (`/pricing`) are EmDash pages** stored in Cloudflare D1, edited at
  `/_emdash/admin`. `seed/seed.json` defines the `pages` collection, its block types, and the
  starting copy. Each block type has a component in `src/components/blocks/`, mapped in
  `src/components/PageBlocks.astro`. `emdash-env.d.ts` is generated by the dev server; commit it.
- **Prices live in the repo**, in `src/data/plans.ts`. The `plans` block draws the cards from that
  file, so the CMS can move the cards but can't change a number. `pnpm check:plans` pins the prices.
- **Docs are Starlight Markdown** in `src/content/docs/docs/`, prerendered to static files.
- Each EmDash page has its own route file (`index.astro`, `pricing.astro`). Don't add a
  catch-all `[slug].astro`: it would also catch `/docs/`, which Starlight owns.
- `mise run site:dev` starts dev with local D1/R2 (in `.wrangler/`) and applies the seed.
  `mise run site:seed` re-applies it to a running dev server; it never overwrites edits.
  To start from scratch, stop the server and delete `.wrangler/`.
- No outside requests from public pages: fonts are self-hosted (@fontsource), and EmDash's update
  check and admin Google Fonts are off in `astro.config.mjs`. Keep it that way.
- EmDash's own agent skills are in `.agents/skills/` (start with `building-emdash-site`).

## Deploying

`wrangler.jsonc` points at the real D1 database `tab-site` and R2 bucket `tab-site-media`.
`mise run site:deploy` runs the checks, builds, and deploys. The first time:

1. Deploy. Wrangler creates the `SESSION` KV namespace (admin sign-in sessions) by itself.
2. Straight away, open https://tab.b28.dev/_emdash/admin. Until someone finishes the setup
   wizard, anyone who opens it can become the admin. Run it on the real domain (passkeys are
   tied to it), create your admin account, and choose to include the sample content: that loads
   the home and pricing pages from `seed/seed.json`.
3. Secrets come from Doppler (project `tab`), synced to the Worker or set with
   `wrangler secret put`, never from `.env` files. Nothing is required today.
   `EMDASH_ENCRYPTION_KEY` (make one with `pnpm exec emdash secrets generate`) is only needed if
   a plugin with secret settings is added.

The Worker bundle is about 2.6 MB gzipped, under the 3 MB free-plan limit. Adding admin
languages or plugins can push it over.

## Development

When starting the dev server, use background mode:

```
astro dev --background
```

Manage the background server with `astro dev stop`, `astro dev status`, and `astro dev logs`.
